# Sub-agents

Use a Sub-agent as a bounded work-placement decision, not as a default team or fixed pipeline. Delegate only when expected improvement in attention partition, trajectory shaping, or capacity scaling repays assignment, Child-model/context/tool, result consumption or validation, integration, conflict, delay, rework, and residual-error cost against the best direct alternative.

The three benefits are evaluation dimensions, not role categories. Compare Primary direct work, progressive loading, a deterministic mechanism, another Agent, and Human-only judgment where applicable.

## Preserve the Authority Star

The Primary owns the global Task, Human relationship, cross-Assignment conflicts, integration, and material residual. A Child owns only one bounded Assignment and its explicitly authorized effect surface. Prefer one writer per mutable target unless an explicit merge boundary exists.

Fit the Assignment to the Child's actual model, context budget, tools, and recovery ability. Let the Child progressively load canonical SVC and project guidance; pass only task delta, semantic handles, snapshot/freshness boundary, non-obvious constraints, consumer, and result/effect contract. Missing context must produce a bounded request, stop, or escalation—not silent scope growth.

## Route the Result to Its Consumer

A semantic information report goes to the consumer that needs to understand and decide; it is not forced through a generic validator. A candidate intended to change shared state uses an appropriate independent validator and effect gate. Evidence or a structured argument is not a mechanical proof unless a trusted mechanism can actually decide the bounded proposition.

Only a material global issue should enter Primary context. Local validator rejection should return to the Child's bounded feedback loop when safe. A Reviewer Agent is not trusted by role; an Agent may execute a verification plan without becoming the verifier.
