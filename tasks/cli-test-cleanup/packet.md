# CLI 测试清理

用户已授权改进 SVC CLI 测试并尽量清理低价值测试。当前为独立侧会话，不使用子代理、不提交，不改 CLI runtime、Corpus、发布工具或主线程任务记录。主线程正在将 Verification 独立恢复，读取时五入口已变为六入口，必须保留这些并发改动。

目标是减少无独立判别价值的测试，修正同源 oracle、真实 HOME 假设、混合非法输入以及正常 update 路径缺口。数量不是独立完成判据，不通过打包多个无关场景伪造减少。保留所有权、秘密保护、路径隔离、并发、回滚及真实协议行为边界。

计划：先审查现有覆盖，删除 CLI 套件中 Corpus 发布工具的测试耦合和纯措辞/内部快照测试；将 CLI schema 发布回归由私有函数替代改为真实临时 Git 输入；让 Skills 正常生命周期通过 CLI 执行；保留特有错误边界与回滚。改动前记录受影响文件快照，编辑时核对没有覆盖并发修改。验证包括相关回归、全部 CLI tests、格式/lint，以及有针对性的错误候选和等价输入，确认判据敏感性。仓库发布工具仍留在 tools，不属于 CLI wheel。

基线：本轮初始实际收集为273例，与主线程此前276记录不同，因为并发恢复了Verification入口，删除对应旧名参数。最终报告分别列出本轮测试删减和期间主线程造成的变更，不把主线程变化算作本轮收益。


已完成。CLI测试273→243例，减少30例（约11%）。按本轮编辑前快照核对，不将主线程变更计入收益。未修改生产代码、Corpus、发布工具、依赖、版本或主线程任务材料，未提交。

删除CLI套件内14例Corpus发布工具回归、重复Skills正常路径、固定帮助措辞、内部IR哈希/布局快照及浅层存储往返。退休Skill名的重复参数组合缩减为代表场景，保留两个宿主、干净删除与修改保护。Corpus发布工具仍由仓库发布检查使用，但删除后不再有这些自动回归测试；CLI schema发布合同仍保留测试。

改进：真实离线ZIP与SHA256驱动CLI安装、采用、检查、升级、删除、重装；默认六个Skill采用独立期望值；显式global目标与已有HOME安装隔离；从有效归档分别注入一个未声明文件或逃逸路径；CLI schema使用真实临时Git历史及公开字段类型变化。Compilation身份判据同时覆盖位置/注释改变保持身份、请求行为改变改变身份。

验证：`pdm run pytest -q cli/tests`最终243 passed（29.40s）；`pdm run ruff check cli/tests`通过；`pdm run ruff format --check cli/tests`通过（58文件）；`git diff --check`通过。没有运行全仓Corpus检查，本轮仅修改CLI测试且主线程正在修改Corpus。

判据实验：故意遗漏默认svc-verification的候选被拒绝；仅改变ZIP成员顺序与manifest JSON格式的等价输入被接受。实验没有持久修改生产代码，仅证明该安装合同的敏感性与表示不敏感性，不推广为整个测试套件的全面证明。没有验证外部网络或Agent实际采用Skill的效果。
