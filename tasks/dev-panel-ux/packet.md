# SVC Dev 面板体验改进

2026-10-28：用户反馈“UI/UX 有点差，你自己看看，改进一下”。这是对已交付资源管理器与 Section 使用体验的修正，沿用已明确的直接实施、自由提交、本机开发签名安装和验收授权。继续遵守不新增自动化测试、不打扰前台；只增加独立观察脚本。`tasks/svc-macos-app/packet.md` 的已有改动不属于本任务。

## 观察与目标

通过 CUA 只读查看实际 0.3.0 面板：用户已创建 InKCre Section，包含 impl-ts 与 impl-py。两个项目仍使用 schema 4，CLI 返回迁移诊断；面板将两段完整诊断、完整路径与逐项目时间全部常驻展示，顶部却显示“0 个资源”。这会把无法读取误表达为没有资源，也使最重要的项目与错误原因难以扫描。此前离屏资源画面还显示，每个动作重复占用两行元数据，资源卡片和 Section 竖线的层级不清楚。

目标是让用户先识别项目和资源，再看状态与可执行动作；保留完整诊断、操作对象和数据影响。App／CLI 权限、资源合同和真实项目配置不变，不推断控制语义，也不擅自迁移项目。产品与技术权威源为 `docs/prd/development.md`、`docs/product-tdd/macos-client.md`、`macos/README.md`。

## 决定与线性实施

1. 简化顶部与底部：顶部使用项目数量及已取得的资源数量，读取失败不显示误导性的零资源；保留刷新和有文字的添加菜单。刷新时间集中到页脚，避免逐项目重复和频繁闪烁。
2. 强化 Section → Project → Resource 层级：Section 使用清晰标题与数量；项目形成轻量容器，资源在容器内使用紧凑分隔；移除重复的嵌套底色与竖线。
3. 项目与资源诊断先展示短原因，完整原文可展开、选择和复制；不靠解析错误文本推断新的业务状态。资源的访问入口直接可见，操作行保留对象和数据影响；实例、来源、时间等技术信息放入详情。
4. 使用实际产品源码生成浅深色画面，覆盖当前迁移错误、正常资源、混合观察、未知结果、长名称和空列表。独立脚本触发实际原生详情控件并记录结果；运行已有原生检查，不新增测试。
5. 更新 App patch 版本及持久文档，提交后核对已检查的构建产物与源码对应关系，再打包，使用本机 Apple Development 证书重装，并核验运行路径、版本、签名和偏好保留。

## 验收判据

当前两个项目的错误在首屏内可扫描，诊断全文仍可取得；读取失败不再声称资源数为零。正常项目中的资源名称、观察状态、访问入口与动作有稳定对齐；宽度受限时不横向溢出，动作对象和数据风险仍在执行前可见。分组折叠、项目归属、刷新与回执语义不变。浅深色、长文案、空状态和错误详情均须检查。自动化测试数量不增加；安装后必须核对实际进程，而不能只看磁盘上的包。

当前处于实施中，用户无需补充设计偏好或重复授权。

## 性能反馈与修正

用户随后反馈整个系统性能下降，并点名临时程序 PanelObservation。首轮同时编译／运行新旧两份观察宿主，并运行既有原生检查；每份宿主保留多扇透明窗口。这个安排产生了不必要的并发与窗口开销，不能用“窗口不可见”推断不会打扰用户。检查时两份宿主与本任务构建已结束，没有剩余的本任务 GUI 进程；额外日志扫描也已结束。正式 `/Applications/SVC.app` 尚未更新。

原生 13 项检查已通过；旧版对照画面生成完成，新版宿主只留下部分画面而没有最终报告，不能称为验收通过。退出的具体原因未确认。随后尝试复用编译模块的低优先级纯离屏脚本，但脚本编译在 90 秒后超时，未启动渲染。已停止追加实验，不再创建隐藏窗口或并行启动 GUI 检查宿主。既有成功检查在适用范围内复用，不重复运行整套检查来补数量。


## 复核与交付准备

只读 advisor 复核了实际 diff、Store／Model、13 项原生检查日志和已取得的浅深色画面，没有发现阻断交付的 UI 或逻辑问题。采用其停止实验、复用既有构建和证据的建议：当前错误场景证明两个项目能同时扫描且不误报零资源，展开截图证明诊断全文可达；正常资源截图保留访问入口、动作对象和删除风险。长文案、空状态和未知执行没有完成本轮全部画面核对，不宣称所有场景逐项通过。13 项检查中只有渲染项完全无窗口，其余原生控件项使用透明窗口；不能将整套检查描述为无窗口。

新增临时观察脚本已删除，保留实际取得的图片、原生检查日志及 validation.json。没有新增或修改测试。当前产品源码在通过检查后未变，打包前核对源码摘要、编译产物时间和二进制摘要；只更新包内版本与签名，不重建配套 CLI。CLI 源码与已安装 18.0.0 完全相同，继续复用其独立环境。
