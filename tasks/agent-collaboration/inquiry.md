# 协作问题与参考依据

本次需要解决的是：不同 Agent 分担工作后，结果怎样可靠地推进共同目标，而不由调用方重复全部劳动；协作持续期间，怎样保持责任、上下文与真实影响的一致。sub-agent 是执行形式之一，独立会话、依赖负责人间的直接协调和责任转移也属于这个问题。

个人 Delegation 指南提供执行形式与持续责任：可采用的结果定义边界，紧密耦合的调查、实施、修复与验证由同一负责人闭环；独立会话保留当前状态及直接人类决定；后续消息传递会改变执行的信息；真正换人才移交责任与在途影响。

factory26 的 SVC 源提供结果采用的核心机制：生成与判断有时成本不对称。复杂搜索可以返回一个含义、条件与实际结果明确的小查询、关系或论证，使消费者不用重新处理全部原始材料。多给出处不自动实现压缩；另一个 Agent 的赞同不自动增加独立证据；没有完整 Oracle 的开放问题仍可委派，返回反例、论据与未知，而非伪造布尔判定。

factory26 的 development-delegation packet 保存具体消息诊断：只读共享源码的限制让恢复负责人无法完成必要局部修复；主会话重复中转已经直接沟通的依赖；催促与重申许可没有改变阻塞条件；组件未完成就宣布 ready 造成重复冻结；旧指令覆盖独立会话较新的用户授权；阶段交付反复切断同一结果的责任。消息次数只能描述现象，不能单独证明协调成本或效果。

当前 svc-sub-agents 已有成本比较、效果边界、能力匹配、单写者与局部修复，可继续使用。需要调整的是固定 Primary/Child 拓扑，以及信息报告与产物分别采用语义读取和独立 validator 的过强二分；信息可以由查询支持，产物也可能需要开放判断。Executor 强制预先列齐验证器、载体和重试预算，让调用方承担了本应由执行负责人解决的细节。

专业边界：协作 Skill 管理工作归属、交互、结果交付与采用；Methods 管理调查/设计/实现本身；Verification 管理判据、证据及反馈质量；Task Packet 管理持久任务状态和恢复。协作入口必须独立可用，但不复制完整专业方法或建立新的运行时、消息协议、角色目录与固定表单。

迁移发现：CLI 的 DEFAULT_SKILLS、采用入口名单及源码检查器都列有 svc-sub-agents；归档校验要求恰好匹配六个名字。换名不能只移动目录，否则旧 CLI 拒绝新归档，新 CLI 也不能简单依靠新名字处理旧安装。当前 Corpus 合同将支持地址变化归为 major；应明确改名后的安装、旧目录与记录处理及消费者路由更新，不默认兼容别名。
