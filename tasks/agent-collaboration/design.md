## 入口的主线

协作是不同 Agent 以各自上下文、能力和行动边界共同推进目标。单个 Agent 的注意力、上下文和能力有限，协作可让另一负责人消化局部复杂性、持续处理反馈或提出不同解释；价值是分担认知与执行负担。交接、等待、协调、判断、整合、错误接受和不必要重做也有成本，选择应与直接工作及确定性机制比较，不做强制评分或默认组队。

由协作产生的问题推导行动：理解分叉要求传递目标和关键前提并核对最新决定；责任断裂要求按完整结果确定稳定负责人和足够权限；采用不确定性要求形成与主张对应的小观察或论证；共享影响要求按真实可变目标协调并处理在途操作。规则及其原因放在一起，不在独立的理论章节解释完再给无因果联系的操作清单。

进入 Skill 时先识别当前所需结果、现有负责人、消费者和协作压力。准备新委派时选择形式并塑造完整结果；接到返回时判断采用依据；已有会话遇到依赖时补充改变执行的信息；责任确需改变时才交接。入口包含足以独立行动的最小指导，不要求按固定阶段执行或读取全部 references。

## 按需深度

`references/delegation-and-adoption.md` 在安排实质工作或返回难以采用时读取。以需要推进的决定或效果为起点，连接可用返回、足够采用依据、执行边界、能力与反馈。接收者负责必要的局部调查、设计、实施与修复，调用者无需事先查清所有文件和执行步骤。通过事实查询与开放设计两个例子说明如何压缩消费者所需处理的信息，同时保留条件、证据来源和未知。采用、具体返修或有界未完成均是可能的结果；不把缺少完整 Oracle 当作禁止协作的理由。

`references/coordination-and-handoff.md` 在持续会话、跨负责人依赖、重定向或责任转移时读取。独立会话保留自己的最新用户决定；获授权的依赖负责人直接协调；消息传递新决定、重要条件与依赖变化、必要问题或真正可采用的交付。采用已有完成事件和合适观察间隔，不反复催促或要求逐步确认。交付需说明实际可消费状态和剩余依赖。转移责任时核对在途操作与共享影响，确认接续者；失联不意味着旧操作已停止。

## 所有权与落地边界

本 Skill 管工作归属、协作推进与结果采用。Methods 管调查、设计与实现本身；Verification 管判据、证据和反馈的专业质量；Task Packet 管持久任务状态及恢复。保留独立使用所需的基本权限、状态和证据边界，按压力发现其它 Skill，不复制完整专业方法、不要求安装依赖。

删除强制 Authority Star 与 Explorer/Executor 角色文件组织骨架，保留总体整合责任、能力匹配、真实效果授权和共享可变目标的明确责任。取消普遍独立 validator、完整文件清单及重试预算前置要求，遵守实际已有的授权和效果闸门。移除规则保护的义务必须在新入口或按需材料中仍有明确所有者。

改名同步框架导航、相邻路由、检查器、CLI 安装与采用名单。Corpus 与 CLI 共同准备 15.0.0。这些调整尚未发布，同一开发线不因每次功能或入口变化逐次升级版本；此前 16/17 的规划已按用户纠正撤回。保持严格当前六名归档合同，不增加别名或自动 rename。CLI 原有名称选择只检查语法，因此显式查询与安全移除旧安装仍可用。迁移先确认目标发行物与安装边界，再移除旧名、安装新名、更新其余实际安装项并独立刷新采用指针；本地修改、第三方安装和消费者自写指导保留各自所有权。各操作是现有独立事务，不承诺跨命令原子性。

内容核对重点是 Agent 能否从协作压力找到第一步，能否说明采用依据与限制，是否让局部失败留在负责人处，并能在共享效果和责任转移时保留真实边界。机械检查验证布局、名称、版本和引用；内容不新增测试，不将静态通过当作真实使用收益。
