## 目标与已有事实

用户需要把自行认定相关的项目放在一起，减少菜单栏面板中的平铺项目，并能按组展开查看各项目资源。这里的 project 沿用 App 中用户选择的项目目录／工作树，不新增工程或任务语义。

[AppStore](../../macos/Sources/SVCMenuBar/Stores/AppStore.swift) 当前按规范化路径去重，将项目路径数组保存在本机 UserDefaults。项目状态、刷新、动作回执独立；资源操作按 CLI 返回的协调身份互斥。[MenuPanel](../../macos/Sources/SVCMenuBar/Views/MenuPanel.swift) 按该数组平铺显示项目，已有添加与移除项目入口，没有用户定义的组或折叠状态。代码中的 ProjectSection 只是单个项目的视图名称，不是用户要求的新 Section。

[产品文档](../../docs/prd/development.md)约定资源管理不推断开发任务；[App／CLI 合同](../../docs/product-tdd/macos-client.md)约定 App 拥有项目来源偏好，CLI 拥有资源解释与控制。这支持把本轮 Section 定位为用户在 App 内组织项目的方式。此前 InKCre 调查中 impl-py、impl-ts 各是独立来源，因此可用“Section InKCre → 两个已有项目”检验层次，不需要改它们的工程配置。

## 已确认的产品方案

Section 是 App 中由用户命名的项目分组，层次为 Section → Project → Resource。分组名称只表达用户自己的组织方式，不推断任务、仓库关系或控制权限。

- 用户可以新建、重命名和删除 Section，并调整 Section 的顺序。允许保留空 Section，方便先建立分组再加入项目。
- 每个 project 至多属于一个 Section，也可以保持未分组。项目菜单提供移入 Section／移出 Section；从 Section 内添加项目时直接归入该组。已有项目再次被选择时定位既有入口，不复制或无提示地改组。
- Section 可展开和折叠，重启后保留分组、顺序和折叠状态。项目原有资源层次、来源路径与回执仍可辨认。
- 删除 Section 时，内部项目回到未分组，保持它们的相对顺序；这不会移除项目、删除配置或停止资源。移动和折叠同样不改变资源操作与协调身份。
- 升级时现有项目保持未分组并保留原顺序。未分组项目直接显示，不要求用户先创建 Section；存在分组时用清晰的“未分组”区域区分。
- 折叠标题保留项目数量，并在组内有执行中操作、失败回执或待恢复的未知执行时提供可展开定位的提示；不把组内多种资源观察合成一个“全部健康”状态。折叠只改变显示，不改变既有观察和执行语义。

建议本轮采用单层、单归属分组。这样用户移动项目时只有一个可预测的位置，添加／移除／回执定位也沿用同一来源。一个项目出现在多个 Section 会引入快捷方式与原项目的区分，本次需求尚没有支持这项成本的证据；如用户确实需要同项目多入口，应先修订产品方案。

本轮不包含嵌套 Section、自动分类、组级启动／停止、跨项目资源合并或共享分组配置。分组属于 App 本机呈现偏好；不要求项目改造，也没有因分组而改变 CLI 资源合同的产品需求。用户已授权按该范围推进；实际实现与证据在下方记录。

## 技术方案与实施准备（第 2–4 阶段）

项目路径数组 `projects` 继续是项目来源的权威，新增 `projectSections` 偏好仅保存 schema 1 的 Section 元数据和“项目路径 → Section UUID”归属。Section 数组拥有分组顺序，每个 Section 保存 UUID、名称和折叠状态；项目在组内沿用原项目数组顺序。因此删除 Section 只解除归属，不重建 ProjectState、不取消刷新或操作，也不改变回执、CLI 协议与资源协调身份。

不存在新偏好时按全部未分组读取，不改旧项目数组。反序列化时验证版本、唯一 ID、有效名称、单归属与引用的 Section；已不在项目来源列表的路径归属可以丢弃，兼容旧 App 移除来源的结果。无效分组偏好保留原值并显示错误，停止分组编辑，项目仍可按原来源使用。正常写入只修改分组偏好；新增／移除项目仍维护原 `projects` 键并调整归属。

AppStore 是所有分组变更的唯一入口，支持创建、重命名、上下移动、移入／移出、折叠及删除。名称去首尾空白、非空且不与其他 Section 忽略大小写后重名。分组变更可以发生在控制动作进行中，但退出等待期间禁止编辑；这些变更不触发资源控制或重置观察。项目重复添加时展开其既有分组并定位原项目，不复制或静默移动。

MenuPanel 顶部添加菜单提供“添加项目”和“新建 Section”；Section 标题可折叠，菜单提供添加项目、重命名、上移、下移、删除。名称在面板内编辑。单项目视图移至 ProjectView；Section 容器单独维护呈现，项目移动入口放在原项目菜单。折叠头的执行／需处理提示从原状态派生：执行由协调 ID 判断，失败与未知由当前资源、项目错误和该项目回执判断，不新增第二份执行状态。窄 NSButton 桥复用到可语义寻址的分组控件。

实施顺序：先增加分组模型与 AppStore 变更接口；随后拆出项目视图并完成分组交互；再更新权威产品／技术／使用文档和 App 版本，最后运行既有检查与独立脚本，检查浅深色画面并完成开发签名安装。App 新增用户能力采用 0.3.0；CLI 仍为 18.0.0，公开结果与配置 schema 不变。

## 验收设计

| 判据 | 条件与观察 | 通过规则 |
| --- | --- | --- |
| S1 升级与持久化 | 隔离旧 projects 偏好；创建、改名、排序、移动、折叠；重建 Store | 原项目顺序／CLI 设置不丢，分组、归属和折叠保留，无重复项目。 |
| S2 安全变更 | 在刷新和控制握手未结束时移动项目／删除 Section，再返回真实 CLI 回执 | 不重发、不取消控制；结果仍归原项目，项目均可找到。 |
| S3 原生使用 | accessory 宿主内操作实际 Section 名称编辑、保存、折叠控件；读取实际列表、菜单项目和资源效果 | 语义对应所选 Section；空组、未分组、长名称可辨，失败／执行提示在折叠时仍可达。 |
| S4 边界 | 空白／重名、重复添加、删除空／非空组、无效偏好 | 无效输入不给成功；删除只解除归属；无效持久数据不被空数组覆盖，错误可见。 |
| S5 回归与交付 | 既有 13 项原生检查，独立脚本、源码与包版本核对、本机安装及重装 | 不新增自动化测试；CLI 不变；真实偏好和项目配置保留，后台启动不抢前台。 |

验收沿用上一任务已验证的隔离 accessory 宿主、NSWorkspace KVO 观察和现有安装工具。脚本只使用临时项目及独立 UserDefaults；真实项目不会为了演示而改组。现有文件选择器、菜单栏锚定和显隐生命周期未改时复用其适用证据，不主动打开用户界面抢前台。必要检查失败先修复其实际原因，不把脚本输出文件存在当作通过。

## 实施状态

实现已完成，CLI 源码、版本、schema 与发布工具均未修改。App 增加 ProjectOrganization、SectionNameEditor、ProjectSectionView，原单项目呈现拆为 ProjectView；AppStore 管理归属和持久化。原生按钮桥增加无边框标题和可压缩尺寸，以便长分组名称不会把右侧提示挤出面板。产品、技术、使用与版本说明均已同步。

[原生脚本](scripts/observe_sections.py)编译实际产品源码，在独立 accessory 宿主中通过实际 NSTextField 的文本变更回调输入名称，通过 NSButton 的语义 ID 保存、重命名、折叠并请求真实 CLI 控制。其余分组动作从 Store 的同一命令入口观察。所有项目、控制者与偏好均隔离；没有新增或扩展测试用例。

[观察结果](evidence/observations.json)支持 S1–S4：原偏好未重写，创建／排序／折叠在新 Store 中恢复；空白与重名拒绝；重复项目不改组并展开定位；控制在途移动和删除分组后只执行一次，回执仍归原路径；失败在折叠标题提示；删除保留原项目顺序；损坏分组偏好保留原值且错误可见。内部激活与键窗口事件均为 0。脚本未驱动 SwiftUI 系统弹出菜单，菜单闭包与 Store 的连接通过源码和编译核对，不能将其称为每项菜单的实际点击证据。
