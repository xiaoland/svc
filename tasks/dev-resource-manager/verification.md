# SVC Dev 验收设计

2026-10-27：本验收设计已获接受，用户已授权并完成第 5 阶段实施，尚未授权第 6 阶段正式验收。本文件拥有跨后续实现、修复与交付回合的判据、证据范围和未验证项，因此独立于技术 Design 维护；它不是实现计划，也不代表任何新行为已通过验收。产品依据是 [开发资源管理](../../docs/prd/development.md)，技术依据是 [已确认的资源合同](../../docs/product-tdd/macos-client.md#资源合同)，取舍背景见 [Design](design.md)。

## 要支持的结论

验收应证明：人和 Agent 可以从项目声明中识别资源，分辨相关状态、可请求动作及影响，通过同一个控制合同完成操作，并理解受证据支持的结果。仅观察、人工控制、等待、失败、未知和共享引用都必须成立。既有控制者继续拥有业务和系统权限，SVC 不靠探测失败宣布停止，也不借界面入口扩大控制权。

本轮判据覆盖已选的项目内资源方案、App／CLI 连通行为、协调与恢复、显式迁移和候选制品。项目外独立登记、自动发现、自动清理、跨主机分布式互斥和通用后台任务不在承诺内，不为这些未承诺能力制造验收义务。四个真实项目提供需求反例，不作为破坏性验收环境。

“满足产品要求”“自动化通过”“用户接受”是不同结论。本设计阶段只判断后续是否有足够的观察方法；实现之后再根据实际证据作通过判断。A01–A18 的设计判据保留；第 5 阶段实际取得的证据与缺口单列在文末。旧版本结果不替代新合同的证据。

## 四条连通旅程与受控资源

| 旅程与真实依据 | 隔离条件 | 应能完成的过程 |
| --- | --- | --- |
| 共享资源及不同控制权，来自 [InKCre](inquiry/inkcre.md) | 临时 owner 项目与引用项目；独立的合成控制者记录请求、拒绝与数据文件效果。 | 从引用入口看到对象和来源，只选择该入口动作；同一控制边界互斥；销毁效果在请求前可见，引用方不会获得 owner 动作。 |
| 服务与连接分别变化，来自 [Velune](inquiry/velune.md) | 本地独立服务与受控连接状态，项目声明显式关系；不连接真实 SSH 或遥测。 | 区分服务可用、连接断开与状态未知；断开连接不被报告为远端停止，可选关联不阻断无关动作。 |
| 安装、运行及人工步骤，来自 [nearby-audio](inquiry/nearby-audio.md) | 临时安装清单、版本文件和运行进程，各自独立；保留 host 作用范围。 | 查看已安装版本、运行状态和人工步骤，调用合成安装／更新入口；工作树来源不产生另一份宿主安装。 |
| 停止必须等待在途工作，来自 [bl-gallery](inquiry/bl-gallery.md) | 合成控制者等待测试拥有的完成闸门，独立写开始、信号、完成及效果记录。 | 请求后看到等待；只有控制者完成才显示对应事实；中断、退出等待和异常恢复不导致隐式重跑。 |

这些替身替代项目内部的 Compose、设备、签名、付费请求或业务逻辑，不替代真实 CLI 子进程、跨进程锁、POSIX 信号、原生控件或公开 JSON 边界。测试结论限于 SVC 如何调用与表达控制者，不能推成真实设备已安装、数据库无损或 SSH 已可靠恢复。

控制者的观察端与执行端保留独立事实：实际文件内容、受控端口响应、安装清单、请求序号、已接收信号和结束事件。SVC 回执用于核对它如何表达这些事实，不能同时充当“实际动作已经发生”的唯一证据。仅需要判断协议解码或罕见错误时才使用固定 JSON／失败注入；至少一条原生控件到真实 wheel 再到真实隔离资源的连通链不能被 mock 替代。

## 判据与观察

下列是行为分组，不要求每行一个测试文件或把每个组合重复跑过所有入口。选择能区分违约的边界；本地规则复用快速检查，跨进程性质和人可见行为保留各自真实边界。

### 声明、状态与控制范围

| ID | 条件与动作 | 观察及通过规则 |
| --- | --- | --- |
| A01 资源形状与唯一来源 | 同一项目包含仅访问、仅观察、人工操作、多方面状态及多控制特性资源；有效 base 与 sparse overlay、缺失 base、旧 schema 和无有效能力的资源分别处理。 | 合法资源无需伪造 provision 或 stop；来源和覆盖结果可解释；非法输入明确拒绝且不改写配置。只接受当前 schema，不从 App 偏好或其它目录秘密补出登记。仅本机 overlay 不能成为独立来源。 |
| A02 查询不代执行控制 | provider 观察和控制动作分别拥有独立调用记录；运行 list、status、自动刷新，故意提供一个明确登记为控制动作的“query”命令。 | list 不运行 provider；status／刷新只调用适用观察入口，不执行控制动作或 owner 脚本。一个观察失败仍返回其它项及动作描述。此项不承诺沙箱能阻止恶意或错误声明的 probe。 |
| A03 身份、引用与能力 | 两入口同名／同 URL 但无共享依据；另两入口显式引用同一直接 owner 且动作集不同；owner 不可解析、引用链和环分别处理。 | 前者不自动合并；后者共用协调边界但保留所选入口，不取动作并集、不借用回执。owner 解析不运行其 probe；缺失 owner 阻止共享控制，独立观察和访问仍可用。非法链／环拒绝，不能退回另一个锁继续执行。 |
| A04 多方面与时间 | 同一资源分别具有安装版本、运行条件和连接条件；组合满足、不满足、未知、单项错误和过期；控制查询时刻前移而 provider 数据时间不变。 | 各方面分别表达，检查时间不洗新旧数据；超过声明有效期的结果不满足完成条件。查询成功不要求条件都满足，未知不变成停止或安全；无统一绿色状态掩盖其它项。使用可控时钟判断有效期，不靠真实长时间等待。 |
| A05 观察协议和实例 | exec 退出码 0／1／其他，结构化状态、非法 JSON／版本／超限输出；HTTP 明确失败响应与不可判定传输失败；worktree 就绪证明匹配／不匹配，以及 host 安装观察。 | 按已确认含义分为满足、不满足、未知或观察错误；原始输出不被猜成指令。worktree 的服务 release 需要对应实例证明，host 安装不被无关 worktree token 拒绝。远端探测选择和现有输出／地址边界保留。 |
| A06 动作影响与人工入口 | 保留、修改、删除及未知数据影响；manual、缺失动作、控制者明确拒绝分别出现；实际操作只触及临时文件。 | CLI 与 App 在执行前表达同一对象、影响和范围；未知不能标成保留数据。manual 给出步骤而不调用 exec，缺失动作不伪造按钮，拒绝不绕路调用 owner／PID。实际删除／保留由文件事实核对，声明文字不是无损证明。 |

### 生命周期、并发与恢复

| ID | 条件与动作 | 观察及通过规则 |
| --- | --- | --- |
| A07 有限命令与完成条件 | exit 命令分别成功／失败；其后条件分别满足、不满足、未知；再构造探测不可达但控制进程仍活着。 | 回执分开报告命令、条件和最终观察；未指定正向停止证明时不报告所有进程已停止。仅命令退出的成功不伪造数据完整或安装就绪，实际进程／文件与报告一致。 |
| A08 就绪释放与独立客户端 | 真实隔离服务尚未就绪、错误实例、就绪、提前退出各分支；CLI 退出后换一个独立客户端观察，再通过声明控制停止。 | 只在正确证明后 release；服务不因就绪后的 CLI、App 或面板退出而停止。第二客户端取得真实当前状态，日志入口可读；停止仅经声明控制者，不使用历史 PID 清理。未就绪失败不得被报告为已释放就绪。 |
| A09 异步控制者接手 | submitted 命令返回，但合成控制者仍持有操作；其后发一个与该操作冲突的请求，最后控制者完成。分别观察退出码提交与显式 JSON 引用；后者覆盖 stderr 日志、缺失／损坏结果和非零退出。 | 首次只报告已接受及实际可用的操作引用。本地锁可释放，第二次真实冲突由控制者拒绝，效果计数不增加；控制者完成前不显示完成。锁空闲不等于底层操作空闲，也不要求 SVC 保留提交锁到远端完成。约定 JSON 引用无效时，即使退出 0 也不造出已接受或资源完成结果，保留实际退出事实与结果错误，不自动重试。 |
| A10 跨进程竞争与等价 | 两个独立 CLI 进程同时请求同入口、同意图 ensure；再分别请求有限动作、不同动作及共享 owner 的另一入口。以控制者握手确保确实重叠。 | 等价 ensure 只有一次实际执行且各调用获得对应事实；其它竞争返回 busy、不错误 join、不在第一个结束后偷偷排队执行。历史有限动作成功不替代下一次明确请求。相同 argv 但不同入口／说明／完成策略不能证明等价。 |
| A11 查看后声明变化 | 获取摘要后改动作、影响、完成策略或 owner；在准备获得锁与 join 前后设置确定的控制边界；另测无期望摘要的直接调用。 | 过期快照拒绝且控制者没有新效果，不自动重试；锁内快照决定实际执行，协调身份变化不会继续沿用错误锁。join 必须对应已发布意图，旧成功不为新声明背书。测试不要求检测外部脚本字节变化，因为摘要未承诺该能力。 |
| A12 信号与等待 | 发布但未启动时取消；wait 动作已开始后依次单独测试 SIGINT、SIGTERM、重复信号；terminate 动作另测期限和信号；对 join 的 follower 单独中断。 | 启动前取消无执行效果；wait 的控制者收不到转发信号，协调锁仍占用，最终返回真实结果而非伪造 130。观察跨过旧终止实现的三秒升级窗口，以杀出旧行为回归；这个窗口不是产品 SLA。terminate 只影响本次拥有的进程，未关联哨兵进程不受影响；follower 中断不终止 owner。 |
| A13 owner-lost 与恢复 | 控制者已开始且继续存活时强杀 CLI owner；另在命令已退出但后置观察被闸门阻塞时强杀 owner，并在完整回执与 settled 已原子落盘后崩溃作对照；连续两个新 CLI 请求及 App 重新读取；错误／过期／跨边界 ID、缺确认参数、正确确认分别处理。 | 领域仍 pending 时持续返回同一未决事实，join 不报成功，已记录的机械退出事实保留；完整 settled 已落盘则正常返回原回执。未决时所有新变更受阻且效果次数不增；错误确认不能解锁。正确确认只解除阻断，原记录仍未知，旧进程不被杀死或宣称结束，也不启动第二次动作。只有随后另一明确请求才可执行。重启客户端不丢失现存 runtime 中的阻断和确认；不声称系统已删除记录后仍有同样保证。 |

## 原生 UI 与不打扰前台的证据边界

验收采用仓库已有的 Swift 原生测试路径，不使用全局鼠标键盘或用户日常浏览器。隔离 UserDefaults、临时项目和候选 CLI；原生控件宿主可以透明、不接收鼠标并禁止激活，用于实际控件到资源效果的链路。这证明控件、Store、CLI 和控制者的连通行为，不能证明生产 App 没有错误的激活请求。

不打扰前台的检查分为两条：

- 隔离宿主记录被测 App／测试进程是否激活或成为键窗口，覆盖整个观察区间。允许用户自行切换其它应用，不能只要求前后 frontmost PID 相等。测试控件不能依据坐标、先后顺序或“第一个按钮”猜动作。
- 正式候选使用产品本来的 accessory 策略与 `--background` 路径，持续观察启动和后台生命周期是否激活。刷新、错误回执与后台退出等待也在实际策略的原生宿主中检查，不能用 `.prohibited` 掩盖这些路径。测试不通过主动打开面板、文件选择器或外部应用来验证它们；这些动作本来就可能按用户意图激活界面。

离屏输出需实际审查浅／深色、长项目名／资源名、共享引用、多个状态、删除效果、未知、等待和错误等代表性画面。判据是内容可见、关联正确、动作可辨、信息不被截断或仅靠颜色表达，兼顾系统字体与可访问名称；PNG 存在或字节数只证明绘制发生，不是视觉通过标准。不以逐像素相等、固定视图层级或助手文案措辞冻结实现。

此前 [App 任务](../svc-macos-app/packet.md) 记录过真实菜单栏首次展示，但未覆盖全部 Finder reopen、系统定位和外部打开。仅当菜单栏入口／锚定实现、环境及相关前提仍适用时，才复用那部分事实；新内容的布局要重新观察。若实施改动了未被隔离原生测试覆盖的系统入口，必须在不影响用户前台的独立 GUI 会话中取得相应证据，或明确保留该缺口，不能用禁止激活的宿主和截图冒充。实施准备需要核对候选变更与这个重验条件，不默认要求用户承担前台验收。

## 观察条件与证据记录

所有资源与数据都由测试创建，loopback 服务使用独立端口，runtime 和偏好隔离，不读取真实四项目配置、凭据、设备或付费数据。并发、中断和崩溃用控制者握手或测试拥有的闸门定位实际阶段；只有旧三秒终止窗口、声明有效期等真正涉及时间的判据使用相应时间条件。等待有独立 watchdog，setup 或等待失败保留为未观察／失败，不自动重试成通过。

清理只关闭测试持有的进程句柄或调用测试控制者的清理入口，不扫描用户 PID 或按端口猜归属。owner-lost 案例刻意留下的子进程仍由测试 harness 掌握真实句柄，最终独立清理。信号、崩溃和清理不借真实数据库、系统音频或安装器来制造故障。

每组证据记录候选 revision／dirty 状态、CLI wheel 摘要、App 来源与构建配置、macOS／Python／Swift 条件、输入声明、初始事实、动作、同步条件、原始结果、独立观察、判据 ID 和限制。失败保存第一份原始证据，修复后的新结果注明候选变化。原生连接证据使用与候选交付一致的配置，并明确实际执行的是测试宿主、CLI wheel 还是正式 App；不把测试宿主标成已安装 App 的完整交互。

结果状态使用通过、失败、条件不足未执行、已有证据适用、范围外；“尚未执行”和“已有测试可复用”不能算通过。选择性执行必须保证必需分组实际被执行或有已核验的复用证据，不能因缺少 `SVC_TEST_CLI`、渲染目录或桌面会话而静默跳过后仍报告全部通过。执行命令与具体文件改动由实现准备制定，本文件不提前替代那个阶段。
