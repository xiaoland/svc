# macOS App 与 CLI 合同

本文拥有 SVC Dev 图形入口与程序化入口之间的职责、公开协议和生命周期合同。产品定位见 [开发资源管理](../prd/development.md)，使用与迁移见[用户手册](../../USER_MANUAL.md)，发行流程见[贡献指南](../../CONTRIBUTING.md#macos-版本与发布)。本文描述 CLI 18.3.0／App 0.2.0 的源码合同；旧版 App 0.1.0／CLI 17.0.0 使用 targets 合同，不能混用。安装和公开发布是独立的交付步骤，不能由源码版本推断。

App 与 CLI 是同一产品能力的两个入口。App 拥有项目来源偏好、呈现、刷新调度、当前会话回执、CLI 路径及项目环境准备／显式 PATH；CLI 拥有配置解释、资源身份、观察、声明动作执行和跨进程协调。项目脚本或实际控制者拥有资源内部的初始化、数据清理、权限和异步操作生命周期。App 不直接读取配置和私有 runtime，也不根据端口或历史 PID 推导权限。

## 本机项目分组

单层 Section 属于 App 的来源组织能力。原 `projects` 路径数组继续拥有项目来源与项目顺序；UserDefaults 的 `projectSections` Data 保存 JSON schema 1，包含有序的 `sections`（id、name、collapsed）及 `assignments`（项目路径到 Section UUID）。一个项目只保存一个归属，组内沿用项目顺序，不生成资源副本。

缺少该偏好时按全部未分组读取，保留原配置。读取时验证版本、名称、唯一 Section ID 和归属目标；不在现有项目列表中的路径归属会被剔除。无法解码或合同无效时保留原始值、显示错误并禁用分组编辑，项目仍可从原来源使用，不能用空分组覆盖损坏数据。写分组由 AppStore 统一负责，不保存观察快照或执行状态。

Section 的创建、重命名、排序、移动和折叠不使项目请求代次失效。删除 Section 只解除归属，控制仍按协调 ID 互斥，回执仍按 entry ID 保存并绑定项目路径。运行提示根据在途操作的项目路径和资源协调 ID 派生，项目暂时无法刷新时也不丢失在途提示。重新添加已有项目会展开并定位原入口，不重复添加或自动改组。

## 公开调用与兼容性

App 在环境准备后通过绝对路径启动独立 CLI，以 argv 传入项目目录；CLI 本身不经 shell 拼接执行。命令结果的权威是[公开输出 schema](../../cli/src/svc_cli/data/output-schemas/)，客户端边界是 [CLIClient.swift](../../macos/Sources/SVCMenuBar/Services/CLIClient.swift) 与 [DevModels.swift](../../macos/Sources/SVCMenuBar/Models/DevModels.swift)。

| 操作 | 命令 | 结果 schema |
| --- | --- | --- |
| 声明及已有执行事实 | `dev list [resource]` | 1 |
| 默认观察或指定方面 | `dev status [resource] [--observation key]` | 4 |
| 明确动作 | `dev act <resource> <action> [--expected-digest digest]` | 1 |
| 恢复确认 | `dev reconcile <resource> --execution id --acknowledge-unknown` | 1 |
| 同名动作便捷入口 | `dev ensure/stop <resource>` | 3 |
| 工作区身份 | `dev identity` | 3 |

以上调用都支持 `--repo`、`--json` 和 `--json-schema`。根 status 结果 schema 为 4，init 结果仍为 4；配置 schema 5 与这些结果版本相互独立。App 校验 command、schema 和必要字段，拒绝不兼容或损坏结果，不能造出成功或未就绪。非零 CLI 退出也可能携带有效回执。

App SemVer、CLI package 版本及逐命令结果版本独立管理。App 0.2.0 配套 CLI 18.3.0，将 dev-monitor 推进到 schema 3，exec／terminate 仍为 schema 1；原 list／status／act／reconcile 的结果版本不变。本开发线包含主窗口、统一的原生导航与工具栏，并沿用系统文字层级和可访问语义；CLI package 的 minor 表示新增独立能力，不由本地 App 迭代次数决定。CLI 17.0.0 已作为 macOS 0.1.0 的公开附件交付，即使未发布 PyPI，也属于兼容性基线。基线选择由 [build_cli_output_schemas.py](../../tools/build_cli_output_schemas.py) 拥有。

机器与执行页使用 `dev monitor --json`，通过重复 --project-root 提供 App 已登记目录，但不依赖项目配置能否解析；`dev terminate <execution-id> [--force] --by human --json` 只请求执行 owner 终止。App 不自己发送进程信号。主机采样、一次性执行及停止证明由[主机与受管执行合同](activity.md)拥有；执行页不会将旧资源动作的 wait、ready 释放或 submitted 改成可强杀。CLI 仍可独立于 App 使用；App 退出不终止前台 CLI 拥有的一次性执行。

## 主窗口与菜单栏面板

Popover 使用单一 ScrollView 承载唯一项目列表，资源视口固定 480 点，内容占满系统提供的视口宽度并保留对称内边距；少量内容也保持相同视口高度，空清单仍使用简短引导。资源开合不再切换“普通列表／滚动列表”两份视图。系统滚动条可以占用自身宽度，内容以实际视口对齐。折叠资源有多个快捷动作、且全部声明不改变数据时，宽度足够便共用一行。其余动作纵向排列，让影响数据的说明紧邻相应按钮。

项目标题省略重复的文件夹图标；首个资源直接跟随项目标题，分隔线仅放在资源之间。项目内资源容器使用较小间隔，资源行不叠加额外上下外边距，项目之间保留较大间隔，以距离呈现归属关系。资源自身的状态、访问、动作与展开内容间距及原生控件命中范围保留。

Section 与项目标题统一使用原生 DisclosureGroup 箭头，保持相同字号和导航起点，并继续约束绑定写入及组内事务以禁用开合动画。项目用量 info 入口位于标题行尾部。资源标题、具名状态和详情按钮使用单个原生 HStack；标题和状态按可用宽度自然换行，不复制布局候选或添加垂直偏移补偿，保留全部既有可见状态、过期提示、悬停与可访问说明。

Popover 只承担状态速览与关键控制：项目没有操作菜单，Section 只作分组与折叠，不提供添加、移动、重命名、排序或移除。空 Section 不显示，空项目清单与 CLI 未配置均引导主窗口；项目添加的应用菜单／快捷键也先打开主窗口。资源状态、访问、声明动作、错误与回执保留；执行页只列当前可观察执行及连接异常，最近记录、正常连接列表和 Agent 接入说明由主窗口承载。主窗口继续提供完整项目管理与执行历史；两处仍共享折叠、数据和控制合同。

菜单栏面板使用紧凑顶部：现有应用标识与标题区作为打开主窗口的原生按钮，更新时间仅显示时间并位于刷新按钮左侧。移除整个常驻底栏及面板加号、设置和退出入口，不额外增加顶部菜单；主窗口和系统应用菜单继续拥有项目管理、设置与退出。保留主窗口入口的可访问名称、快捷键及时间的完整悬停说明。

App 在既有 AppKit 应用入口中使用唯一 MainWindowController，承载 SwiftUI NavigationSplitView 及其原生工具栏，不增加第二个 AppStore。AppKit 使用 fullSizeContentView 与 unified 标准窗口样式，并保留固定标题；NSHostingController 只桥接 SwiftUI 工具栏，全部按钮和系统侧栏按钮由 SwiftUI 统一管理，不再叠加手工 NSToolbar。侧栏选择全部资源、Section、项目或全局执行；项目内容复用 ProjectView、ResourceRow 及同一操作回执。Section 折叠沿用已有本机偏好，项目折叠在本次 App 会话中由 AppStore 的 collapsedProjects 路径集合统一拥有，两个界面共享而不写入偏好；页面选择及资源详情展开分别由两个界面的视图持有。删除当前 Section 或移除当前项目后，主窗口回到全部资源，不保留失效选择。

打开菜单栏 Popover 时，App 捕获状态栏按钮的屏幕坐标，并在本次展示期间使用同位置、透明且不接收鼠标事件的原生锚点。系统菜单栏重新排版时，已经打开的 Popover 保持定位；关闭时释放锚点，下次打开重新取坐标。

普通启动及 Finder reopen 唤起主窗口；`--background` 只影响启动时呈现，不激活前台。Popover 和应用菜单（Cmd-0）可打开已有主窗口，最小化时恢复该窗口。主窗口采用标准关闭、最小化、缩放和调整尺寸行为，`SVCMainWindow` frame autosave 保存位置与尺寸。主窗口或设置窗口打开期间为 regular 应用，可在 Dock／Cmd-Tab 中访问；两者都关闭后回到 accessory 菜单栏常驻。关闭最后一个窗口不退出应用，资源与一次性执行也不因此停止。设置仍为独立窗口，退出继续等待本 App 的在途控制操作。

AppStore 持有按 panel／mainWindow 区分的观察需求；窗口宿主负责可见性，视图只通知资源页是否被选中。主窗口关闭、最小化、应用隐藏或完全遮挡不产生可见需求；Popover 按实际展示状态登记。主机与项目各有一个周期循环，间隔为上一轮完成后 5 秒。任何可见界面需要资源时才运行项目循环。移除需求会取消后续周期，但保留正在自然结束的循环占位，快速重新显示也不产生第二个循环。CLIClient 的在途调用不会因关闭窗口被强杀。单项用户刷新和操作后的刷新仍沿用已有去重及代次规则，不属于额外周期采样。

## 指令结果通知

AppStore 在校验并保存 OperationReceipt 后调用一次完成回调，覆盖 App 主动发起的 dev act 和 dev reconcile，包括请求、协议或身份校验失败形成的无结构化结果回执。AppDelegate 在 willFinishLaunching 注册并持有 UserNotifications 委托；CommandNotifications 只投递现有回执，不增加后台观察。首次回执到达时异步请求原生通知授权，多个结果共用一次授权请求，后续读取系统授权状态，已有授权时等待系统确认排队后才释放操作并完成在途退出；等待授权不占用操作互斥，不阻止后续指令或退出，拒绝或投递失败不改变操作回执，原生授权与声音／预览／横幅由系统设置拥有。

设置使用原生 Form 显示当前系统通知权限；初次未决定时可主动请求授权，未允许时可打开系统通知设置，已经允许时可发送明确标记的测试通知。权限从已安装 App 的 UserNotifications 读取，设置窗口初次加载、成为关键窗口及 App 重新激活时刷新，不另存偏好或轮询。系统授权请求不会重复展示已经处理过的提示；调用返回、通知排队和实际横幅展示分别取证，不根据临时同名宿主或调用成功推断用户已看到提示。

标题按公开 ActionReceipt.status 表达 completed、ready、accepted、reused、manual、busy、condition-unmet、owner-lost、failed、interrupted、stale、absent、acknowledged 和 nothing-to-reconcile；缺少可信结果及未识别状态均明确为未确认。completion 的 submitted 对应回执 accepted，不能写成任务成功。通知正文携带动作意图和有长度上限的原回执消息，按项目聚合；每次操作用新的通知 ID，周期刷新不重发。前台委托同样允许系统展示横幅、通知列表及声音。

通知携带项目路径及自身展示摘要。点击默认动作只打开唯一主窗口，展开并选择仍登记的项目，显示带通知时间的原摘要；已移除的项目明确说明，不自动重新登记或执行指令。主窗口复用已有 projectReveal 导航信号，资源回执仍按原有入口保留最新一条；通知摘要由系统保存，不另建结果数据库。外部 CLI／Agent 执行清单不是本次通知来源，不能由消失或粗粒度状态推断成功。

## 进程与安装关系

一次请求对应一个 CLI 子进程。App 不额外给控制请求加短超时；退出等待在途操作，用户可取消退出，取消退出不取消动作。就绪释放后的服务不随 CLI 或 App 退出；移除来源和关闭面板也不是停止指令。观察和会话回执不作为下次启动的新鲜事实；运行证据由 CLI 保存，App 只使用公开回执中的日志路径。

App 依赖用户安装的系统可用 CLI，不捆绑 Python 或 CLI，也不在 App 安装期间创建 Python 环境、安装 wheel 或改变用户的 CLI 版本。CLI 路径留空时，在准备好的项目终端环境 PATH 中查找 svc；用户选择自定义 PATH 时沿用其显式路径。准备结果按项目与显式刷新代次复用，动作仍走同一 CLI。显式绝对路径优先，不存在时不偷偷换用另一版本。App 的默认环境准备读取用户登录交互 shell 并完成项目钩子，带截止时间、独立进程组及失败缓存；自定义 PATH 保持兼容，不把构建机 PATH 写入包。详见[项目执行环境合同](macos-execution-environment.md)。旧安装器留下的 SVC 私有 runtimes 路径恢复为自动查找，其余用户偏好保留。缺少共享 CLI 时，每个界面只提示一次安装或选择路径。按项目终端环境自动查找时，某个项目查找失败仍在该项目显示原因。两个界面和设置提供 GitHub latest release 与 PyPI 安装入口；协议不兼容时明确要求升级或选择兼容版本，不自动安装。公开发布可以交付同 commit 的独立 CLI wheel，manifest 记录协议与版本，安装仍由用户完成；macOS CD 不自动发布 PyPI。安装和信任条件见 [macOS README](../../macos/README.md) 与 [INSTALL](../../macos/INSTALL.md)。

## 资源合同

### 声明与身份

配置 schema 5 使用项目内的 `dev.resources` 替换固定 `dev.targets`。`svc.json` 与同版本 `svc.local.json` 共同形成一份有效声明；不新增项目外登记库或后台服务。资源至少提供观察、访问或人工／自动操作之一，包含具名观察、具名动作和明确关系。五类控制特性可以组合，不对应五种执行器。App 保存项目来源偏好，CLI 独立按 `--repo` 解析项目；资源作用位置可以是远端或设备。

入口身份由所选项目／工作树与资源键确定。控制协调身份沿用当前 namespace、scope、scope ID 与资源键生成规则，直接迁移同名同范围资源时保留原锁边界。实际观察到的实例身份由控制者或探测提供，未知时不推断。URL、PID 或显示名相同都不构成自动合并依据。

共享 owner 只能显式引用另一项目中的直接资源声明，不允许引用链或环。引用提供共享协调身份，不继承 owner 的动作或权限，也不自动执行其观察和依赖。请求保留所选入口及其声明，控制者仍可拒绝。owner 无法解析时拒绝共享控制，不退回本地锁；独立观察和访问可以继续返回并说明关联错误。普通关系不产生控制顺序。本机协调不承诺跨用户、跨主机或项目脚本直接调用的互斥。

### 观察与动作

观察按具名方面分别返回结果、来源、检查时间、错误及可选值和实例。控制者的数据时间与 SVC 检查时间分开，过期观察不能满足动作完成条件，单项失败不抹去其它项。HTTP／TCP／exec 是观察手段；不可达不独立证明停止。exec 明确选择退出码格式或版本化 JSON，退出码格式约定 0 满足、1 不满足、其它为观察失败，JSON 格式表达 `satisfied / unsatisfied / unknown` 及可选显示值、说明、数据时间和实例身份。默认刷新只调用声明为自动观察的入口；任意项目脚本不因此获得无副作用保证。

动作具有稳定键、意图、作用对象、控制特性、数据影响与完成合同。效果缺失保持未知，人工入口返回明确步骤，不能被客户端补成自动操作。自动完成方式为：`exit` 等有限命令结束并检查可选正向完成条件；`ready` 取得就绪和所需实例证明后释放本次拥有的长驻进程；`submitted` 只确认实际控制者已接受请求。最后一种方式要求控制者拥有后续身份、冲突处理和生命周期，本机锁仅保护提交过程。回执分别表达请求、执行、完成条件和各项最终观察，不能以命令退出或 readiness 为 false 推导数据已保留或资源已停止。

submitted 默认使用声明的退出码合同，0 仅表示接受请求。需要返回动态操作引用时，动作显式选择 `operation-json`；控制者通过 `SVC_DEV_RESULT_FILE` 写入本次执行的独立结果文件，结构为 `{"schema_version":1,"operation":{"id":"控制者操作ID","url":"可选访问地址"}}`。不从合并日志提取 JSON。该通道要求严格字段和类型、至多 64 KiB 的普通非链接文件，以及沿用访问入口许可规则的 URL。命令退出 0 但约定结果缺失或损坏时保留真实退出事实并报结果无效；实际提交可能已发生，不能自动重试或声称资源操作完成。

有限命令的 `wait` 策略在启动后不因 SIGINT／SIGTERM 或客户端等待期限终止动作，保持协调所有权直到真实结束；启动前取消不再启动动作。`terminate` 只适用于声明可中断的动作，仅能终止本次仍拥有的进程。`ready` 也只用于未就绪时可安全终止本次启动的情况。App 不另加短控制超时，无取消能力时不提供虚假的取消成功；沿用等待操作后退出或取消退出。没有独立后台托管承诺。

### 协调与恢复

同一协调身份上的控制请求互斥。有限动作不缓存历史成功，遇到竞争返回 busy，不隐式排队。ensure 式动作通过正向条件收敛，只能加入同入口、同动作、同解析意图的在途执行；跨入口或相同 argv 本身不证明等价。查看后执行的请求绑定有效声明摘要；CLI 在锁内重新解析入口、owner 和动作，协调键或摘要变化时拒绝替换执行。join 另行核对请求与在途快照。摘要覆盖解析到的声明和执行输入，不冻结外部脚本字节。

机械进程退出与 dev 动作结算是两个事实。动作保持 ExecutionRecord schema 2，以 `operation="act"` 区分；dev 补充记录按 execution ID 保存入口、动作、摘要、pending／settled／owner-lost 阶段和回执。持锁重载、检查旧未决事实后，先写机械记录及 pending 元数据，再发布协调指针，最后启动；必要记录发布失败不得启动。完整回执与 settled 必须原子保存，join 等领域结算而不是仅等机械退出。失去生命周期锁时仍 pending 即构成 dev owner-lost，即使机械已经 exited／released 也持续阻断，并保留机械真实结果。旧 ensure／stop 记录可以没有新元数据，新 act 记录缺失或损坏元数据不能假定为旧格式。

未解决的 owner-lost 持续阻止同一边界上的后续变更，查询和观察仍可用。恢复必须引用当前未决 execution ID 并明确承认原结果未知、重试可能重复；恢复只解除阻断，不执行动作、不改变原未知结果，也不证明原进程结束。确认在锁内检查并先原子记录，再允许另一明确请求覆盖协调指针；确认不把 dev owner-lost 改成 settled，不能根据历史 PID 接管。runtime 留存条件见[本地执行运行时](../deployment/execution.md)。

### 接口、呈现与迁移

共同公开入口是 `dev list`、`dev status`、`dev act <resource> <action>` 和 `dev reconcile <resource> --execution <id> --acknowledge-unknown`。list 解析声明及已有执行事实，不运行 provider probe；status 获取观察，不执行控制动作。ensure／stop 仅在对应明确动作存在时可用，不任取第一个动作。reconcile 无确认参数时只返回未决事实。最终字段由同步更新的公开 schema 与客户端模型强制，App 不解析配置或私有执行记录。

list／status 的 0 表示请求取得可判定结果，不要求所有条件满足；未知或部分观察失败返回 3 并保留有效项。act 的 0 表示声明的完成合同成立，submitted 仍只表示接受；busy、人工操作、声明过期、条件未满足和未解决 owner-lost 返回 3，配置或执行错误返回 4，真正取消／终止返回 130。wait 收到信号后正常完成时保留实际完成结果，退出码不能代替结果对象。

App 按来源展示资源及具名状态，详情承载实例依据、关系、动作影响和回执，较强后果在执行前可见。观察按入口与方面保存，操作按协调身份互斥，回执保留所选入口和 execution ID；共享身份不合并权限和反馈对象。旧刷新不能覆盖操作后状态，切换 CLI 或移除来源使对应观察失效。混合资源不使用统一就绪计数，也不把所有实现细节堆在列表中。

面板使用无卡片的原生 DisclosureGroup 区分项目，项目默认展开，收起时仅保留项目标题、在途操作及需处理提醒；展开后保留资源、诊断与回执，用量由标题 info 按钮打开。显式定位项目会展开项目及其 Section，移除项目清理本次会话的折叠状态，折叠不改变采样或控制。没有 Section 归属的项目直接列出，面板与主窗口侧栏都不增加“未分组”标题，Section 标题不显示项目数量。Section 菜单沿用与原生项目披露标题一致的尾部留白，以省略号和资源箭头的实际符号中心核对操作列，不能只比较控件外框宽度。列表填满滚动视口的可用宽度，并使用对称水平内边距；主窗口的有宽度上限内容列在详情区居中，列内文字仍左对齐。顶部的资源数量只统计已取得的快照；任一项目未成功读取时，不将此数量描述为完整总数，全部未知时省略数量。DiagnosticView 仅截取诊断的首段用于列表显示，完整原文保留在展开区；不根据错误字符串推断配置版本或资源状态。默认保留具名状态、首个网页入口及运行／连接快捷动作，其他动作和路径按需展开；修改、删除和未知的数据影响在操作前可见，保留数据的完整影响说明按需展开。观察来源、时间和实例等证据也在详情中。详情开合是视图局部状态，不写入资源或 Section 偏好。

资源、执行和诊断按钮直接使用 SwiftUI Button，ResourceActionButton 仅汇总原生样式、角色、禁用、悬停和可访问元数据；没有 NSViewRepresentable、Coordinator、自定义尺寸测量或动作注册表。Store 继续拥有操作事实；展开状态仍由视图局部持有。原生可访问名称与稳定标识保留，验收工具适应标准控件，不为隐藏宿主的命令式点击改造产品。离屏展开重放若显式设置初态，必须说明其范围，不能当成真实指针或 VoiceOver 验收。

配置遵循 current-only 人工迁移，不新增双读或旧字段别名；现有 `${dev.target}`／`SVC_DEV_TARGET` 脚本接口继续表示所选资源键。先保持资源键、scope 和 host_key 迁移声明形状；引入 owner、改名或改变 scope 属于协调身份变更，必须先完成旧边界的活跃或未解决执行。没有持久身份映射时，不承诺任意热改身份下的跨键互斥。旧客户端的 follower 可能取得锁后继续旧快照，因此停止发起旧控制并排空全部旧 owner／follower 后才开放新版控制。保持相同协调键只保证旧 owner 持锁时新请求不并行，不能把新版 owner-lost 规则强加给旧等待者；不能通过强杀旧调用伪造已排空。公开结果和 App 一起迁移，CLI、App 和结果 schema 仍分别管理版本，不兼容组合明确拒绝。


## 项目范围与用量

App 0.2.0 的主窗口在全部项目、Section 或项目范围内保留原生资源／执行切换；侧栏“全部执行”包含未归属记录。项目范围的列表直接显示有当前执行的项目分组，用量入口位于分组标题旁。执行列表使用“当前执行”和“最近记录”，避免将仍有可观测进程的 owner-lost 描述为已结束；它仍明确显示结果未知并禁用终止。项目筛选只使用 monitor 返回的 project_path 精确匹配 App 已规范化的来源路径，不在客户端根据 cwd 或命令内容重新归属。项目和执行展示来自同一 monitor 快照的用量；资源详情通过 entry_id／project_path 关联仍可观察的本地资源运行。App 不因观察到 released 进程而提供直接终止按钮，资源继续走声明动作。

机器概览始终保留全机含义，磁盘读写、swap 已用量与真实换入／换出不会随所选项目变为该项目的值。项目用量明确标为“已观测”，不涵盖未接入的外部程序、容器或远端工作；不可用显示不可用而不是零。Swift 模型保留指标不可用时的空值表达，不伪造读数。本机及配套发行使用 18.3.0 的 monitor schema 3；旧 monitor schema 1／2 明确拒绝混用。exec／terminate schema 1 与资源配置 schema 5 不变。

## 默认信息与深入查看

机器概览常驻一行压力状态；过期采样、未知压力和部分指标不可用仍明确显示。点击整行打开原生 popover，不在项目列表上方展开长指标表。浮层先显示压力结论与建议、CPU、内存、磁盘和 Swap 活动；采样时长、核心数、普通换页及压缩速率由“采样与底层指标”进一步展开。过期快照不显示当前调控建议，读数统一受过期提示限定；不可用值仍显示不可用。浮层可关闭，内容有高度上限并可滚动，机器含义不随项目选择改变。项目路径在项目菜单中保留，默认不占一行。项目资源占用入口为标题旁的原生 info 按钮，项目收起时仍可打开 popover，列表不再单独放 CPU／内存摘要行。弹层显示 CPU、内存、占本机容量的比例、进程数、磁盘读写、页面读入、执行／资源数及统计边界。未采样、未观测到进程、指标缺失或过期均明确区分，不显示虚假的零。

项目 info 颜色由 App 的 ProjectUsagePressure 拥有，属于展示启发而非 CLI 信号或 OS 项目级内存压力：项目 CPU 的单核百分比除以逻辑核心总容量，50%／80% 提示黄／红；macOS footprint 占总内存的 20%／40% 提示黄／红，任一维度达到即提示。RSS 不代替 footprint；未知容量不代入零，I/O、页面读入、主机 swap 不参与着色。采样过期或完全没有可比较指标时使用中性；部分统计不完整时可对已观察到的高占用发出提示，中性不意味着完整或正常。弹层内的颜色说明拥有可见规则，不新增用户配置、后台采集或控制权限。

资源默认显示运行就绪方面，以及不满足、未知或过期的观察；其它满足的观察按需展开。没有上述方面时显示首项具名观察。客户端不据此把不同条件改写成通用运行／停止状态，也不把未满足当作故障。资源名称与具名观察组成紧凑摘要；未过期且满足的观察以勾号表达状态，保留观察名、完整悬停提示与无障碍文字，未满足、未知或过期仍显式显示文字。默认保留首个 HTTP(S) 访问入口和声明含 runtime／connection 特性的快捷动作；其余安装、供应、观察及未分类动作在展开后可用，不依据命令、名称或当前满足状态推断动作含义。资源展开后先补充其余具名状态、全部访问／路径复制入口、全部声明动作、手动检查与用量；观察值、原始命令、精确时间戳、实例、控制者、协调范围、关系及动作分类放入独立且默认收起的“诊断信息”，不会随着第一层展开直接铺满卡片。声明的人工步骤与动作完成方式仍跟随操作呈现。修改、删除或未知的数据影响始终紧随可点击的对应动作，不移到诊断层；这次收敛不削弱既有控制合同。

执行行默认保留名称、实际状态、CPU／内存摘要与可验证的普通终止入口。项目、cwd、来源、argv、日志、ID 和完整用量在详情中；强制终止也在详情中，并保留独立确认。owner-lost、终止中和未知状态仍在收起时可见。最近记录继续默认收起，Agent 接入说明放在执行列表菜单。所有详情开合仍为局部视图状态，不增加持久配置，不改变采样与控制权限。

对已有明确图标的常见控件统一省略重复动作文字：添加、展开、普通终止、设置、刷新和设置中的文件选择。悬停提示、无障碍名称、稳定标识和展开状态仍保留。菜单项、声明的资源动作、保存／取消、强制或破坏性动作继续用文字说明具体操作，Section 名称、机器状态和访问地址等对象内容也不能作为冗余标签删除。

项目 info 按钮使用中性、黄色或红色反映已观测占用；hover 和无障碍名称保留文字状态，弹层明确不可用与过期。单项目资源页不再同时显示外层项目标题和项目折叠标题。单项目执行页将同一 info 按钮放到项目标题旁，多项目范围保留具名入口；无数据也可打开原因说明，不产生空卡片。空执行清单不另显示零计数。资源展开后把动作说明直接放在对应按钮下面，不再次重复动作标题或数据影响；图标菜单与关闭入口也保持完整的悬停提示。

压力浮层中的底层指标、项目颜色说明、最近记录与侧栏 Section 的 DisclosureGroup 保留系统控件，但每处局部 transaction 同时设置 animation 为 nil、disablesAnimations 为 true，避免默认展开／收起过渡造成内容缩放、淡入或布局迟滞。该约束不施加到整个窗口，也不改变展开状态的所有者、Section 偏好或刷新调度。做法来自 nearby-audio 的修复提交 `027c894`，不复制其项目业务。

原生执行与机械执行共享项目列表，但采用独立模型。HarnessExecution 保留来源、scope 和动作能力；HarnessExecutionRow 仅在来源允许时展示日志／停止，停止前显示原管理器的作用范围并确认，不提供外部 force。IntegrationSettingsView 消费同一 ActivityStore 的 integrations，在设置内安装 Pi 桥接或配置现有 Codex socket；Claude 从用户 PATH 自动发现。执行页的折叠来源状态区区分尚未接入与空清单，沿用原生 DisclosureGroup 的局部无动画处理。连接、身份失效、日志预算和用量限制由 [activity 原生来源合同](activity.md#原生-agent-执行来源)拥有。


DisclosureGroup 的展开绑定使用 immediateDisclosure，在写入展开状态的 transaction 中清空 animation 并设置 disablesAnimations，再以相同事务写回原绑定；保留组内已有的事务约束。只改组内收到的 transaction 不能约束父容器与相邻区域的布局更新，所以不能作为整次开合已禁动画的依据。压力底层指标、项目颜色说明、执行来源、历史与侧栏 Section 采用同一入口；没有新的展开状态副本，不改变原生控件、键盘或可访问语义，也不全局关闭动画。
