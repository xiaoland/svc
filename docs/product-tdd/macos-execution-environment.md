# macOS 项目执行环境

本合同由 App 的 ProjectEnvironment、CLIClient、CLIConfiguration 与 AppStore 实现；CLI 的配置解释、动作、run、摘要和进程控制合同不变。目标是在同一用户正常新终端进入项目后的开发环境中，取得一致的 CWD、工具选择及项目配置覆盖，无需为了 GUI 再维护一套项目工具配置。任意既有终端会话的临时 export、TTY、alias、函数不属于可隐式复制的输入；CLI 和声明动作继续通过 argv 执行。

## 环境来源与模式

没有自定义 PATH 的现有安装与新安装默认使用“项目终端环境”。App 使用账户的登录 shell（zsh／bash），从 HOME 开始读取登录、交互启动配置，然后以独立参数进入目标项目目录，完成已有目录钩子及首个 prompt hook，再取得导出环境。zsh 使用 chpwd 与 precmd／precmd_functions，bash 使用 PROMPT_COMMAND；不解析或改写启动文件，不硬编码 cargo、Node 等工具路径，不自行激活特定版本管理器，也不代替用户执行 mise trust、direnv allow 或安装工具。mise 目录／prompt hooks 的含义见[官方说明](https://mise.jdx.dev/shell-setup.html)。不支持的登录 shell 明确报错，可显式选择自定义 PATH；依赖 TTY 的启动逻辑可能在准备阶段失败。

已有非默认 PATH 保留为“自定义 PATH”：继承 App 环境并用已设置 PATH 替换，沿用原有效行为，不悄悄迁移到 shell 模式。用户可在设置明确切换，原路径保留以便切回；executionEnvironmentMode 保存模式，旧偏好缺少该字段时根据原有效 PATH 判断。CLIConfiguration 的程序化构造默认仍为 fixedPath，以保留显式客户端／既有检查的语义；AppStore 为普通用户配置选择默认模式。

显式 CLI 绝对路径始终优先，失效时不替换为另一个版本。自动查找 CLI 在准备完成的环境 PATH 中进行；准备前的静态查找只用于自定义模式提示，不作为自动模式缺少 CLI 的结论。全局 monitor／执行来源操作使用 HOME 环境，项目请求使用项目环境；全局入口不会借用某个项目的工具配置。

## 一次准备、显式刷新

ProjectEnvironment actor 按项目路径和 App 配置代次共享准备 Task，包括失败。周期采样、状态和实际动作复用同一环境，避免不断执行启动代码或给摘要引入新的会话变量。工具配置、启动文件或项目环境改变后，用户点击刷新或保存设置重新准备；AppStore 同时使旧观察请求和快照失效。已有在途动作时不切换环境，动作继续沿用发起时的环境。刷新不是配置内容的自动监听，也不保留跨 App 重启的缓存。

缓存保存内存中的完整导出环境；准备结果通过 0700 临时目录内的 0600 文件传递，启动输出与结果通道分开，退出后清理，不将完整环境或任意启动输出展示、记录到日志或保存为偏好。每次准备在 utility 工作任务内运行，有 5 秒截止时间和 2 MiB 输出上限；使用独立进程组，超时／超量终止该组并收回本次 shell；App 正常退出时也停止其拥有的准备进程组，不触碰 CLI 动作或资源进程。启动脚本本身仍是用户代码，可能创建脱离该进程组的辅助进程；App 不宣称它无副作用。失败有明确阶段，不回退到另一 PATH，且在刷新前复用失败，避免周期重试。

## 执行与失败

准备只提供 CLI 的调用环境。dev 的 action.env 继续覆盖它；run 的 env_files、entry.env 继续按已有顺序覆盖，不让 shell 再覆盖项目声明。App 不重定义 dev／run 的环境摘要规则；同一准备快照用于 status 和 expected-digest 动作，刷新后须取得新快照。CLI 在实际执行前重新检查有效声明，配置变化仍会阻止过期动作。App 不尝试把相同命令、不同环境或不同来源改写成同一执行身份。

准备失败／超时返回环境准备错误，并明确项目命令尚未执行；启动输出可能含凭据，不直接作为错误原文展示。环境准备成功而找不到 CLI 使用明确的缺少 CLI 原因，界面提供安装／选择入口。CLI 动作失败继续保留真实退出状态与既有操作日志；不会改写成准备失败，也不会自动重试安装或控制动作。

验证使用真实 CLIClient 的有限探针与独立正常终端入口对照 CWD、工具路径和选定变量；在临时项目及 HOME 中检查实际 CLI 的 action.env、run 覆盖和 expected-digest。固定 PATH、缓存与失败缓存、显式刷新、项目切换及阻塞 hook 进程组清理分别验证，不通过运行真实项目重装或制造压力负载验收。具体工具版本或新 shell 支持需要独立验证，设计本身不证明任意 shell 初始化逻辑等价。
