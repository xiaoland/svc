# Grow a Task Packet

Use this guidance when the lightweight shape check in Task Packet exposes current or foreseeable pressure on Human recovery, Agent retrieval, local planning, or concurrent editing. It helps select and migrate to a sufficient shape. Growth is an in-place semantic refactor, not a scale score, lifecycle event, or CLI decision.

## Run a Shape Preflight Early

Expand the entry's lightweight check only for the pressure identified:

1. Can short `packet.md` plus one linear plan control the foreseeable work?
2. Does the plan exceed 30 lines or need independent revision history? (Split to `plan.md`)
3. Can two or more work lines advance in parallel, with completion times differing by more than one day? (Use a Task Map with multiple Tracks)
4. Which inquiry, design, decision, or verification state has a distinct retrieval/update owner now? (Split to information modules)
5. Where would two writers contend, or where is current truth already hard to recover?

Fix the likely shape while the move is cheap, but do not create speculative Tracks or modules. Re-run the preflight when work topology, freshness pressure, evidence volume, or collaboration changes materially.

## Stable Root Entries

The common root vocabulary is deliberately small:

```text
packet.md
plan.md                 # only when the plan exceeds 30 lines or needs independent revision
track-*.md              # only when using a Task Map with multiple Tracks
inquiry.md              # optional information owner
design.md               # optional solution owner
decisions.md            # optional decision register
verification.md         # optional cross-return qualification synthesis
```

A stable entry may grow into same-stem supporting depth, for example `design.md` plus `design/`, or `decisions.md` plus decision shards.

## Migrate in Place

1. Select the owner or topology pressure before selecting filenames.
2. Create the stable entry from the applicable asset template only when it helps.
3. Move the current semantic content before adding new analysis.
4. Replace the old location with a compact projection or route; do not keep two competing current truths.
5. Repair Track relations and the Human `packet.md` projection in the same change.
6. Verify that a fresh Human can recover the outcome/current issue from `packet.md`, and that an Agent can find each active owner without broad search.

Unknown or custom names are allowed when they carry real task-local value. Review unfamiliar names for an identifiable owner and useful return rather than renaming them merely to fit this vocabulary. Shrink or remove a module when its management return no longer repays synchronization and navigation cost.
