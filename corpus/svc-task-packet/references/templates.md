# Task Packet Template Family

## Purpose and Activation

This family provides opt-in building blocks for a non-trivial Consumer Task whose control surface or admitted topology needs recovery at a stable address. Use [`packet.template.md`](../assets/packet.template.md) for the minimal entry; select another file only after its topology or information owner is admitted. Do not copy this directory as a prebuilt task tree.

## Ownership and Boundary

`packet` owns the compact Human collaboration projection. `plan`, `task-map`, and `cell` own work topology at their respective levels. `inquiry`, `diagnostic-matrix`, `design`, `decisions`, and `verification` own distinct information returns. The family does not own product truth, implementation source, automatic orchestration, or a completed-work log; each Consumer owns the instantiated state.

## Selection Logic

- [`packet.template.md`](../assets/packet.template.md) is universal and is the only default bootstrap. Use it for Objective, Guardrails, terminal Verification, Current Truth, and Next Step.
- [`plan.template.md`](../assets/plan.template.md) is for one owner's current partial route with ordered Slices or an honest TBC continuation condition.
- [`task-map.template.md`](../assets/task-map.template.md) is for admitted Track/Phase topology and integrated barriers, not a list of assignments.
- [`cell.template.md`](../assets/cell.template.md) is for a real participating Track × Phase coordinate with a shared integration return.
- [`inquiry.template.md`](../assets/inquiry.template.md) is for a bounded question or decision with evidence and freshness pressure.
- [`diagnostic-matrix.template.md`](../assets/diagnostic-matrix.template.md) is an optional Inquiry artifact for competing causes and discriminators, not an alternative whole-Task packet.
- [`design.template.md`](../assets/design.template.md) is for unresolved forces and a coherent proposed solution; [`decisions.template.md`](../assets/decisions.template.md) is for accepted decisions that need an address beyond the conversation.
- [`verification.template.md`](../assets/verification.template.md) is for an owned claim whose qualification, trusted-base scope, or requalification needs its own return beyond the packet's terminal Verification.

Template existence never proves that a file should be created. Keep pressure inline when the packet remains recoverable; create a child only when its owner, consumer, and return are distinct. Do not add implementation, delivery, acceptance, retrospective, Track, Phase, Slice, Agent, or generic-module templates to this family.
