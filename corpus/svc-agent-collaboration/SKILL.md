# Agent Collaboration

## Assign a Complete Outcome

Start with the needed outcome, owner, consumer, and reason to collaborate. Compare context isolation, independent judgment, and parallelism with transfer, waiting, correction, and integration costs; direct work or deterministic tools may suffice.

Before delegating, decide what you will do meanwhile. Delegate parallel work, noisy investigation, or independent judgment. When the assignment is your own critical path and you would only wait, compare doing it directly.

Parallel assignments are worth their overhead only when each owns a genuinely distinct, non-overlapping outcome. When assignments share most inputs — the same code regions, files, or domain context — parallelism multiplies reconnaissance cost without multiplying useful output; a single owner who builds understanding incrementally is usually faster and more coherent. For a multi-part task, keep connected sub-problems under one assignment unless sub-problems affect separate targets or require genuinely independent judgment. Sending the same full task to multiple agents in parallel is not parallelism; it is duplication.

Recurring assignment shapes have role starting points under `assets/`: an [Explorer](assets/role-explorer.md) answers a bounded question through adaptive evidence acquisition and returns a report with resolvable handles, a [Design Explorer](assets/role-design-explorer.md) generates and shapes design directions as comparable candidates when the main work's incumbents would force early convergence, and an [Executor](assets/role-executor.md) owns one bounded development loop from real input to evidence. A role shapes the assignment's boundaries and return; it grants no authority beyond the assignment itself.

Admit a new role reluctantly. Review is a verification strategy, not a standing role: a generic second opinion reproduces the trust paradox instead of resolving it, so assign review only when a specific residual risk needs a fresh evidence path, and let a trusted mechanism or the Human remain the validator. Promote a one-off contract to a reusable role only when it performs like a deep module: a compact context interface, substantial coherent work behind it, and a credible local acceptance or escalation path. For designing or evaluating a role, read [Designing Roles](references/designing-roles.md).

Assign one owner a complete, usable outcome: purpose, current decisions and state, starting points, completion criteria, authority, and effect limits. Keep connected investigation, design, implementation, operation, repair, and verification together. Write the return arrangement into the assignment itself, because the assigned Agent may not read this guidance: work independently, message during execution only for a blocker, a changed premise, or a result that releases a dependency early, and put everything else in one final return. For independent judgment, pass the Human's original words, the goal, evidence entrances, and the decision to resolve, in a fresh context, and leave your preferred answer out. For unclear work boundaries or capability needs, read [Delegation](references/delegation.md).

## Execute Independently and Return

The assigned Agent independently resolves local uncertainty and recoverable failures, verifies its work, and delivers one final return. When the host delivers that return automatically, do not separately message the completion content. The caller continues its own work without requesting progress or directing each step. Learn whether the host wakes the caller when the return arrives; with no independent work left, wait once with a timeout suited to the task, and report to the Human only meaningful changes.

Interact during execution only for a changed premise or blocker that cannot wait until final delivery, or a usable result that releases an actual dependency early. When progress depends on a missing Human-specific fact, authority, or consequential goal or tradeoff decision, raise the smallest decision-ready issue and continue unaffected authorized work. Informational messages need no acknowledgment; needed decisions and responsibility transfers require a response, and silence grants no authority. For these exceptions or overlapping effects, read [Coordination](references/coordination.md).

## Adopt and Continue

Adopt through evidence or reasoning whose meaning and limits you understand, without repeating the entire investigation. Agent agreement and action reports alone prove no result. Before adopting a proposal that narrows scope or lowers a standard, check it against the Human's original words. Return concrete repair reasons to the same owner. For an unclear basis for adoption, read [Adoption](references/adoption.md).

A final return ends an execution turn, not responsibility for an unfinished outcome. Reuse the owner for repairs; after completion, reuse its context when helpful and establish the new outcome and authority limits. Each follow-up is a new complete outcome; giving the same owner each next step every few minutes signals a wrong boundary, so widen the outcome and authority or take the work back. Reuse grants no permanent domain ownership or additional authority.

The overall Task owner retains integration, cross-task priorities, Human communication, and unresolved obligations. Human goals, preferences, permissions, consequential tradeoffs, and acceptance retain their authority. Permission to create or message Agents, write, or cause external effects comes from host and project authorization; where they allow it, choosing to delegate is an ordinary judgment for completing the Task. Before replacing an owner or recovering interrupted work, read [Handoff](references/handoff.md).

Reuse the Task's existing state. Return decisions, evidence, pending effects, and next actions to its owner; delegation creates no separate Task or Packet. Keep durable truth at its project owner.

The overall Task owner finishes the collaboration when the outcome is adopted and integrated. If no feasible, authorized continuation can close a material gap at proportionate cost, return the supported partial result, unmet condition, current owner, pending effects, and smallest next action. Preserve the surrounding Task's remaining obligations.
