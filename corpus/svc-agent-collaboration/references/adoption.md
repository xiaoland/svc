# Adoption

Read this as the delivering Agent or consumer when a return's basis is difficult to understand or judge. It expands the entry's result-use guidance; produce an adoptable result, specific repair request, or explicitly unresolved claim.

Make the return easier to judge than the search. Identify the actual candidate, inputs, result, and decisive observation or argument, including conditions and limits. A query or explanation may compress extensive investigation; a pile of links that requires reconstructing it does not. A launch receipt establishes an attempted action, not its achieved effect. Obtain source observations when consequences or uncertainty require them, and use applicable project effect gates without inventing a universal validator.

For example, when switching views loses an unsaved filter, an Agent can compare preserving it, visibly resetting it, and asking before discarding it. Return causal reasons, the counterexample of a hidden filter making a view appear empty, and observed use when available. The consumer can judge a reversible candidate without replaying every design attempt. Without observed use, the result remains a reasoned proposal; another Agent's preference supplies no user observation.

Reuse evidence whose assumptions and connection to the current candidate still hold. A concrete contradiction, changed premise, or missing observation should become an actionable repair request to the original owner, who handles local correction and verification. A new candidate or interruption does not invalidate all earlier conclusions. Where further evidence is unavailable or disproportionate, accept only the supported part and retain the gap explicitly; adopting a partial return does not complete the surrounding Task.

When criteria or observations need design or repair, optionally discover `svc-verification` by name through the host if available.
