# Delegation

Read this as the caller when work boundaries or capability needs are unclear. It expands the entry's assignment guidance; produce an assignment whose owner can independently deliver something the consumer can use.

Choose the boundary around the consumer's decision or needed effect and the evidence or reasoning that could support it. Open design can use reasons, counterexamples, or observed use without a complete test oracle. Do not prescribe the answer to make adoption easy.

Supply relevant known state, source entrances, dependencies, constraints, and excluded effects. The caller need not discover every file or local fact first: the assigned owner establishes source identity, affected consumers, and facts needed for its work. File boundaries coordinate edits without creating approval requirements for every necessary file inside an already authorized effect. Preserve others' changes; general infrastructure improvement belongs in the assignment only when completion depends on it.

Match actual judgment, tools, context capacity, recovery ability, and feedback to the work. A narrow outcome can still be difficult. A sub-agent may isolate noisy investigation; an independent session may better support durable context, a separate lifecycle, or direct Human interaction. Retained context saves work, but stale assumptions or the need for independence can justify a different Agent.

Seek independent judgment when it can change a consequential choice. Give the original goal, evidence entrances, and decision to resolve rather than requesting endorsement; shared assumptions can correlate errors. Ordinary execution failures stay with their owner. Repeated requests for local instructions suggest fragmented responsibility or inadequate authority; repair the assignment rather than coordinating every step.
