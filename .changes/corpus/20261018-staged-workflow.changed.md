默认阶段式工作流细分为产品需求设计、技术方案设计、验收方案设计、实施准备、实现与反馈、验证与交付，按用户已授予的范围推进；开工复核归入准备到实现的边界。阶段式参考承接 Agent 自主调查与推导、提交连贯方案、用户质疑与整体修订、授权对象判断及实施准备的交互细节；执行计划应尽可能线性清晰，不遗留决定方案成立与否的先验实验或资料确认待办。转段前先核对已有授权：覆盖下一阶段则直接推进，未覆盖才请求用户授权；用户无需使用阶段名称或固定批准用语。持续迭代式工作流保持原有节奏。

入口描述简述人机协作流程和探索、设计、规划、实施方法，所有非平凡任务读取并使用；不再把流程问答设置为独立触发条件。入口保留阶段和授权规则；提案、反馈或准备需要更多指导时读取阶段式参考，复用已在上下文中的内容。同步消费者入口与迁移指导，常驻规则与实际指针由消费者维护。

Workflow 先确定当前应交付的阶段结果，再选择方法、工具和 Agent 分工。当前结果已可评审且下一环节尚待授权时，应交回用户并保留整体任务的剩余工作；功能目标或源码效果权限不自动取消阶段复核。协议在正文及参考中自包含，不依赖改强消费者全局指令或在description中复制执行规则。阶段内仍可自主调查技术事实，既有阶段决定和明确覆盖后续环节的授权继续复用。

作者合同要求description简短、中立地概括主要指导，并仅在有助于识别受支持工作时添加简明使用条件；漏读会话本身不构成新增用途的依据。执行协议由正文和条件参考承载。

其余五个Skill的description同步精简，保留Task Packet覆盖所有非平凡任务的范围，补齐Taste在产品或技术事实不能决定选择时使用的条件。作者合同借鉴ASD-STE100的相关原则，要求description、入口和参考沿用语义所有者的术语与含义，使用直接动词和清楚条件消除歧义，并保留授权、义务、范围和不确定性的区别。

阶段表直接链接对应可用方法及设计视图，说明按需读取，不要求依次执行。实施准备在入口明确列实现计划、解决草案暴露的缺口，再收敛为尽可能线性清楚的执行顺序。Task Packet的恢复指导区分已确认决定、观察、提案和Agent推断，按来源、状态及适用范围判断其效力，沿用仍适用的决定与证据，处理冲突或过时内容；记录提案不构成批准，历史问题不自行产生当前任务义务。
